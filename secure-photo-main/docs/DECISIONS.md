# Журнал решений

## 2026-09-28

- Рабочая директория создана в `/home/ubuntu/secure-photo` согласно разделу 11 спецификации.
- Выбран стандартный Node.js WebCrypto и JDK/JVM без сторонних криптографических библиотек для этапа 0.
- Указанный в окружении GitHub-репозиторий недоступен через GitHub CLI, поэтому работа начата в локальной директории; это не меняет структуру и требования проекта.
- Этап 0 проверен на Node.js 22.13.0 и OpenJDK 21.0.12: ECDH P-256, HKDF-SHA256, AES-256-GCM и формат `65 + 12 + ciphertext` совпадают в обоих направлениях.
- Зафиксированный Node-вектор использует неизменяемые receiver/eph ключи, IV `00112233445566778899aabb`, AAD `interop-photo-0001`; неверный AAD и изменение байта ciphertext отвергаются.
- Владелец подтвердил наличие домена и VPS; целевая версия Android — Android 15.
- Для водяного знака выбран текст `все для тебя любимый Л`.
- Уведомления не входят в обязательный MVP этапа 1; приложение должно обновлять список при открытии и по кнопке, а push/FCM остаётся на этапе 4.
- Для сервера выбраны проверенные версии Fastify 5.12.5, `@fastify/cors` 11.3.0, `@fastify/rate-limit` 11.2.0 и `better-sqlite3` 12.6.2. Версия 13.0.3 при проверке на Node.js 22 дала native segmentation fault даже на `:memory:`, поэтому не используется.
- Этап 1 принят локально: `npm run build` и `npm test` проходят, 6 тестов зелёные; проверены `MAX_ROOMS`, bearer-auth, лимиты PUT, атомарная гонка последнего просмотра, идемпотентный `X-Open-Id`, TTL/cleanup, ротация sender_secret и удаление.
- Этапы 2–6 реализованы в репозитории. Фактический домен владельца не был указан, поэтому Android содержит явные URL-заглушки `https://secure-photo.example`, которые нужно заменить перед release-сборкой.
- В текущем sandbox нет Android SDK/Gradle/Docker, поэтому Android instrumentation, `docker compose up` и ручной чеклист `adb` требуют выполнения на машине владельца/VPS; статический web JSON/XML и серверный build/test проверены локально.
